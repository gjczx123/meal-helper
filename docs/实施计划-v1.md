# 三餐助手 · 无人值守改造 实施计划

> **给执行者：** 逐步实现，每步先写测试。规格见 `docs/设计方案-v1.md`，执行前先读它。

**Goal:** 每天三个固定时间自动在微信提醒她报备三餐，读取她的文字/照片回复记入台账，能识别就回一句，识别不了就安静记录。

**Architecture:** 纯逻辑层（解析、判定、话术、状态机、调度）与系统层（Win32 输入、微信读数）分离；系统层薄、可替换，纯逻辑层 100% 单测覆盖。

**Tech Stack:** Python 3.13（`E:/Qianwen/python/python.exe`）、ctypes/Win32、sqlite3、cryptography（SQLCipher 解密）、Pillow（截图）、requests（视觉 API）。**不引入** pyautogui / pyperclip / uiautomation / schedule。

**Spec:** `docs/设计方案-v1.md`

## Global Constraints

- 目标机：Windows 10/11，150% 缩放，微信 4.2.0.12，进程名 `Weixin.exe`，窗口标题 `微信`
- 数据目录：`<你的微信数据目录>/`（从配置读，不写死）
- 只用已安装的依赖：stdlib + pillow 12.3 + cryptography 50.0.1 + requests 2.34.2；测试用 stdlib `unittest`（pytest 未安装）
- 所有文件路径用 `pathlib.Path`；中文内容统一 UTF-8
- 时间一律本地时区，不做时区换算
- 每餐等待窗口 30 分钟，轮询间隔 15 秒
- 任何异常都不许让常驻进程退出；必须写日志并通知

## Review Focus

下面五类输入/故障，规格里没写死但一定会遇到，每条都要有对应测试：

1. **否定句**：她说「没吃米饭」「今天没喝奶茶」，不能被记成 1 份 → Task 2 测试
2. **语音消息**：她发语音，程序不能崩、不能判 normal、不能回复 → Task 2 + Task 4 测试
3. **重复处理**：重启或轮询重叠时同一条消息被回两次 → Task 4 测试
4. **发送校验**：消息发出去了但发到了错的人 / 发了两条 → Task 8 测试
5. **读库抛错**：微信升级导致解密失败，进程不能死 → Task 10 测试
